# 데이터의 자리들

`loggia-data.json` 의 각 자리가 무슨 꼴이고 무슨 규칙을 지키는가.
갱신할 때 필요한 대목만 꺼내 본다.

```bash
grep -A 20 '^## 비용' tools/DATA.md
```

빌더와 같은 자리에 있으므로 어긋날 일이 없다. `build.py` 를 고치면 이 글도 고친다.

## 뼈대

```
meta          제목과 갱신일과 한 줄 메모
statuses      상태의 어휘
indexKinds    색인의 어휘
thinkers      이론가의 이름표와 찾을 말
readings      읽기 묶음
sections[]    now 진행 중, waiting 결과 기다리는 중, later 아직 손대지 않은 것
  items[]     id, title, venue, kind, status, dates, next, note, uses, chats[], links[]
compass       연구 지형도
decisions[]   정한 것
reuse[]       다시 쓸 것
people[]      사람
repeats[]     해마다 돌아오는 것
archive[]     끝난 것. review 에 심사평
venueGroups[] 낼 곳의 무리
  venues[]    id, name, sub, type, url, indexes[], flag, deadline, 비용, review, 답까지, note
watch[]       공모를 지켜보는 자리
memo[]        기억해 둘 것
```

날짜는 `dates` 안에 `deadline`, `sent`, `decided` 셋이다.

## 다섯 장이 무엇을 보여주나

| 장 | 무엇 | 어디서 나오나 |
| --- | --- | --- |
| 현황판 `index` | 진행 중과 아직 손대지 않은 것, 정한 것 | `sections`, `decisions` |
| 달력 `calendar` | 답을 기다리는 중, 해마다 돌아오는 것, 열세 달 | `sections.waiting`, `repeats` |
| 낼 곳 `journals` | 저널·학회·레지던시·공고, 길목, 새겨 둘 것 | `venueGroups`, `watch`, `memo` |
| 재료 `materials` | 이론가·개념·읽기, 다시 쓸 것, 사람 | `uses`, `thinkers`, `readings`, `reuse`, `people` |
| 지난 일 `archive` | 끝난 것과 심사평 | `archive` |

취업 갈래 하나가 움직였을 때 판을 따라 움직이게 한다.

## 갈래를 고칠 때

`loggia-data.json` 의 `sections` 안이다.

| 일어난 일 | 손댈 곳 |
| --- | --- |
| 진척이 있었다 | 해당 `items[]` 의 `next` 와 `note` |
| 마감이 바뀌었다 | `dates.deadline`, 그 갈래의 `venue` 쪽 `deadline` 도 함께 |
| 냈다 | `status` 를 `제출` 이나 `심사` 로, `dates.sent` 를 채우고 `waiting` 칸으로 옮긴다 |
| 결과가 왔다 | `archive[]` 로 옮기고 `dates.decided` 와 `review.gist` 를 적는다 |
| 새 갈래가 생겼다 | `sections[0].items[]` 에 더하고 낼 곳이 새로우면 `venueGroups` 에도 |
| 대화를 이었다 | `chats[]` 에 `date`, `summary`, `url` |
| 무엇으로 짓는지 알았다 | `uses` 의 `이론가`·`개념`·`읽기` |
| 폴더만 있고 아직 안 시작했다 | `later` 칸에 `status: "미착수"` 로 |
| 판단을 내렸다 | `decisions[]` 에 `date`, `what`, `why`, `item` |
| 다시 쓸 글감을 알았다 | `reuse[]` |
| 누구에게 무엇을 부탁했다 | `people[]` 의 `마지막` 과 `메모` |
| 해마다 돌아오는 마감을 알았다 | `repeats[]` |

## 첫 칸을 고르는 규칙

현황판 맨 위 "지금 이것부터"는 `build.py` 가 스스로 고른다.
마감이 있고 `next` 가 적힌 것 가운데 가장 가까운 것이다. 손으로 정하지 않는다.

## 낼 곳을 고칠 때

`loggia-data.json` 의 `venueGroups[].venues[]` 안이다.

| 일어난 일 | 손댈 곳 |
| --- | --- |
| 지면을 새로 알았다 | 알맞은 무리의 `venues[]` 에 더한다 |
| 색인을 확인했다 | `indexes` 를 고치고 클래리베이트로 대조했으면 `"clarivate": true` |
| 특집 마감이 떴다 | `deadline` 과 `note` |
| 비용을 알았다 | `비용` 을 갈래로 나눠 적는다 |
| 심사 속도를 알았다 | `review` 에 글로, `답까지` 에 날수로 |
| 해마다 돌아오는 마감이다 | `repeats[]` |
| 자리가 정해졌다 | `flag` 에 "Plastic 논문 1순위" 처럼 |
| 문이 닫혔다 | `flag` 에 "접수 중단", `note` 에 사정 |
| 지켜볼 자리 | `watch[]` |
| 저널 아닌 곳을 알았다 | 학회·레지던시·공모·교원 공고도 `venues` 다 |

## 낼 곳의 무리

지금 걸려 있는 곳 / 영화·영상 이론 / 철학·미학 / 예술·시각문화·매체 /
국내 등재 / 주제는 맞으나 비등재.

투고했거나 마감이 걸린 지면은 `지금 걸려 있는 곳` 으로 옮긴다. 끝나면 제자리로 돌린다.

## 갈래와 낼 곳이 저절로 이어진다

`items` 의 `venue` 가 `venues` 의 `id` 를 가리키면
낼 곳 장의 그 지면 아래에 무엇을 냈고 어떻게 되었는지가 저절로 붙는다.
지면 쪽에 그 이력을 손으로 적지 않는다. 두 번 적는 셈이 된다.

## 재료

재료 장은 이 두 가지에서 글을 거꾸로 찾는다.

### 이론가는 저절로 걸린다

**대개 아무것도 적지 않는다.** `note` 나 `next` 에 이름을 쓰면 그것으로 족하다.
빌더가 `thinkers` 의 `말` 에 적힌 이름을 항목의 글에서 찾아 잇는다.

> "슈미츠의 반신적 공간을 1절에 넣었다" 라고 메모에 쓰면 슈미츠가 걸린다.
> 따로 태그를 달 일이 없다.

그러니 이론가를 쓴 사실을 남기고 싶으면 **메모 안에서 그 사람을 부르면 된다.**
이름을 감춘 메모를 쓰고 태그를 따로 다는 것보다 짧고, 잊을 일도 없다.

`uses.이론가` 는 **메모에 이름이 없는데 실제로 쓰는 경우에만** 적는다.

새 이론가는 `thinkers` 에 더한다. 이때 `말` 에는 **사람 이름만** 적는다.
학파나 개념 이름을 넣으면 잘못 걸린다. '신현상학까지는 넓히지 않는다'는 메모는
슈미츠를 쓴다는 뜻이 아니기 때문이다.

한 사람을 더하면 **이미 쌓인 메모를 거슬러 훑는다.** 예전 항목도 그때 함께 걸린다.

### 개념과 읽기는 손으로 적는다

```json
"uses": {
  "개념": ["아우라", "매질"],
  "읽기": ["atmosphere-corpus"]
}
```

개념은 자유롭게 적되 **이미 쓰인 말을 먼저 본다.** 같은 것을 두 이름으로 부르면
재료 장에서 두 칸으로 갈라져 셈이 틀어진다.

개념은 저절로 걸리게 하지 않는다. 이름과 달리 부정문이나 딴 뜻으로 스치는 일이 잦다.

`읽기` 는 `readings` 에서 고른다. 파일 하나가 아니라 읽기 묶음을 가리킨다.
정독노트 예순 편을 낱낱이 적지 않는다. 그 묶음의 드롭박스 폴더 하나면 된다.

## 정한 것

무엇을 왜 그렇게 정했는지 남긴다. 반년 뒤에 같은 논의를 다시 하지 않기 위해서다.

```json
{ "date": "2026-07-29", "item": "balazs",
  "what": "발라즈 논문을 Film-Philosophy에서 MIRAJ로 돌렸다",
  "why": "접수를 닫았고 재개를 짐작할 근거가 없다" }
```

`item` 은 있으면 적고 없으면 뺀다. 현황판 아래에 접혀서 새 것부터 쌓인다.

## 답을 기다리는 중

달력 맨 위다. `dates.sent` 가 있고 상태의 결이 `wait` 인 것이 저절로 오른다.
며칠째인지는 브라우저가 센다.

지면의 `답까지` 에 날수를 적어 두면 그것을 넘길 때 붉어지며 물어볼 때라고 알린다.
**모르면 적지 않는다.** 지어낸 날수는 없느니만 못하다.

## 해마다 돌아오는 것

```json
{ "label": "발표 제안 마감", "venue": "scms",
  "months": [8], "day": 25, "짐작": true,
  "note": "해마다 공고를 볼 것" }
```

`day` 는 숫자이거나 `"말일"`. 달력이 해마다 다시 셈하므로 해가 바뀌어도 이어진다.
확실하지 않으면 `"짐작": true` 를 단다. 달력에 짐작이라고 찍힌다.

지면 하나에 관해 새로 안 것을 판에 앉힌다.

## 비용

한 줄로 뭉치지 않고 갈래로 나눈다. 무엇이 얼마인지가 바로 보여야 한다.

```json
"비용": {
  "심사비": "12만 원",
  "게재비": "30만 원",
  "연회비": "7만 원",
  "연회비 납부": "확인 안 됨",
  "APC": "있음, 금액 미확인"
}
```

이름은 자유롭게 짓되 이미 쓰인 말을 먼저 본다.
심사비 게재비 연회비 연회비 납부 투고비 APC 회원비 기타.
모르는 것은 적지 않거나 "확인 안 됨"이라고 적는다. 금액을 지어내지 않는다.

연회비 납부처럼 해마다 돌아오는 것은 `repeats[]` 에도 넣으면 달력에 찍힌다.

## 답까지

그 지면이 대개 며칠 걸리는지다. 숫자만 적는다.
달력의 응답 시계가 이 값을 넘길 때 붉어지며 물어볼 때라고 알린다.
저널이 밝힌 값이나 셈할 근거가 있을 때만 적는다.

## 색인은 함부로 적지 않는다

클래리베이트 MJL 이 유일한 근거다. 출판사 페이지는 양방향으로 낡는다.
확인하지 않았으면 확인하지 않았다고 `note` 에 적는다. 지금 대조가 끝난 곳은 둘뿐이다.

## 상태와 색인의 어휘

상태는 `statuses` 에서 고른다. 자유롭게 적지 않는다.
준비 미착수 집필 교정 조사 구조 제출 심사 대기 선정 게재 반려 보류 종료 상시.

색인은 `indexKinds` 의 열쇠말로 적는다.
`ahci` `ssci` `scie` `esci` `scopus` `kci` `kcic` `erih` `doaj` `none`.
앞에 빼기표를 붙이면 미등재다. 보기 `["ahci", "scopus"]` 또는 `["scopus", "-ahci"]`.

## 거르개

현황판 위에 상태로 고르는 단추가, 낼 곳 위에 색인과 마감으로 고르는 단추가 있다.
**손으로 만들지 않는다.** 지금 판에 실제로 있는 상태와 색인만 빌더가 세어 단추로 낸다.
새 상태를 쓰면 단추가 하나 늘고, 그 상태를 아무도 안 쓰면 단추가 사라진다.

거르개가 도는 원리는 이렇다. 상자마다 `data-tags` 에 열쇠말이 적혀 있고,
누른 단추의 열쇠말을 가진 상자만 남는다. 빈 마디는 접히고 셈도 다시 센다.

## 접기

**오늘 할 일이 아닌 마디는 접는다.** 펼쳐 둔 것이 많으면 무엇부터 볼지가 흐려진다.
빌더가 이미 그렇게 짓는다. 지금 접혀 있는 것은 정한 것, 해마다 돌아오는 것,
다시 쓸 것, 사람이다. 펼쳐 둔 것은 진행 중과 기다리는 중과 답을 기다리는 중,
곧 지금 손이 가야 하거나 남의 답이 늦고 있는 것들뿐이다.

새 마디를 더할 때 이 갈래를 지킨다. 할 일이면 펼치고 참고할 것이면 접는다.

## 손댄 날

`dates.touched` 에 마지막으로 그 갈래를 만진 날을 적는다.

마감만 보면 마감 없는 갈래가 조용히 가라앉는다. 손댄 날이 있으면 판이 알아서 말한다.
이레까지는 조용하고, 여드레부터 주황으로 "n일째 안 움직임", 스무하루부터 붉게
"n일째 멎어 있음" 이 된다.

**갱신할 때마다 그 갈래의 `touched` 를 오늘로 고친다.** 이것을 빠뜨리면
실제로 움직인 갈래가 멎은 것으로 보인다.

## 걸음

`next` 한 줄 대신 `steps` 에 차례로 여럿을 적을 수 있다.

```json
"steps": ["추천인 세 통 발송", "파일 최종 확인", "8월 4일 제출"]
```

첫 걸음이 크게 뜨고 나머지는 그 아래 차례로 놓인다. 하나를 끝냈을 때
다음이 이미 거기 있으므로 다시 생각할 필요가 없다. 시작하는 값이 비싼 사람에게 이것이 크다.

`next` 만 있어도 된다. 그때는 걸음이 하나인 셈이다.

## 품

`품` 에 그 갈래의 다음 걸음이 얼마나 걸릴지 적는다.
`십분` `한시간` `반나절` `며칠` 넷 가운데 하나. `efforts` 에서 고른다.

현황판 거르개에 품 단추가 함께 서므로 **지금 이십 분밖에 없는 날에도**
할 수 있는 것을 골라 볼 수 있다. 크기를 모르면 손이 안 떨어진다.

## 해치운 표시

다음 걸음 옆의 네모는 이 기기에만 남는다. 데이터를 건드리지 않는다.
갱신하면 사라진다. 진짜 기록이 아니라 오늘의 매듭이다.
정말 끝난 걸음은 `steps` 에서 빼고 `touched` 를 오늘로 고친다.

## 지난 서른 날

현황판 맨 위에 낸 것과 끝난 것과 손댄 갈래의 수가 뜬다.
`dates` 의 `sent`, `decided`, `touched` 를 브라우저가 세는 것이라 따로 적을 것이 없다.
