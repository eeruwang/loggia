# 워커

워커 하나가 두 가지 일을 한다. 다섯 페이지를 내주고, 아침마다 편지 한 통을 부친다.

```
   클로드 ─▶ 깃 푸시 ─▶ 깃허브 ─▶ 워커 빌드 ─▶ 워커
                                              ├─▶ 브라우저  (다섯 페이지)
                                              └─▶ 편지함    (아침 일곱 시)
```

클로드가 판을 고치는 길은 그대로다. `fetch.sh` 로 받고 `build.py` 로 만들고
`publish.sh` 로 올린다. 올라간 것을 클라우드플레어가 알아서 받아 배포한다.
클로드는 클라우드플레어를 알 필요도 없고 그쪽 키를 쥘 일도 없다.

---

## 저장소가 어떻게 생겼나

```
wrangler.jsonc        워커의 설정. 저장소 뿌리에 있다
package.json          wrangler 와 타입
tsconfig.json
worker/src/index.ts   워커의 몸
public/               워커가 내주는 것. 다섯 페이지와 글꼴과 _headers
tools/                빌더와 봉인 도구
data.enc              하나뿐인 데이터
digest.enc            아침 메일이 읽는 꾸러미
```

판이 사는 자리는 `public/` 하나다. 2026년 8월 1일에 깃허브 페이지에서 옮겨 왔고,
뿌리에 있던 사본 다섯 페이지와 `CNAME` 과 `.nojekyll` 은 그때 치웠다.
같은 판이 두 자리에 있으면 언젠가 한쪽이 낡는다.

`data.enc` 와 `digest.enc` 는 뿌리에 둔다. 내주는 것이 아니라 받아 가는 것이다.
`fetch.sh` 는 깃으로 받고 워커는 raw 로 받는다.

## 한 번만 하는 일

### 1. 빌드를 저장소에 붙인다

Workers → 해당 워커 → **설정 → 빌드**.

| 칸 | 값 |
| --- | --- |
| Git 리포지토리 | `eeruwang/loggia` |
| 빌드 명령 | 없음 |
| 배포 명령 | `npx wrangler deploy` |
| 루트 디렉터리 | `/` |
| 프로덕션 분기 | `main` |
| 경로 포함 | `*` |

`package-lock.json` 이 저장소에 있으므로 의존은 알아서 깔린다.
`경로 포함` 을 `*` 로 두는 것이 맞다. 갱신할 때마다 `public/` 이 달라지므로
매번 다시 배포되어야 한다.

> **빌드 화면의 「변수 및 암호」는 여기가 아니다.** 그 칸은 빌드를 돌릴 때만
> 쓰이는 값이다. 워커가 살아 움직일 때 쓰는 비밀은 아래 3번 자리에 넣는다.

### 2. 메일 길을 연다

**Email Service → Onboard Domain** 에 올릴 것은 뿌리가 아니라
**`loggia.moonilsun.com`** 이다. 판을 내주는 그 이름 그대로다.
MX, SPF, DKIM, DMARC 넉 줄이 그 아랫가지에만 들어간다.
뿌리 `moonilsun.com` 의 MX 는 손대지 않는다.

한 이름이 두 일을 겸해도 부딪치지 않는다. 판을 내주는 것은 A 와 AAAA 레코드고
편지를 세우는 것은 MX 와 TXT 다. 종류가 다르므로 나란히 산다.
사용자 지정 도메인과 Onboard Domain 은 어느 쪽을 먼저 해도 된다.

**Email Service → Destination addresses** 에 `moon@ilsunmoon.com` 을 넣고
확인 메일의 단추를 누른다.

| | |
| --- | --- |
| 보낸다 | `info@loggia.moonilsun.com` · 아랫가지. 클라우드플레어가 서명한다 |
| 받는다 | `moon@ilsunmoon.com` · 뿌리. 쓰시던 편지함 그대로 |

확인된 주소로 보내는 편지는 **어느 요금제에서나 값이 없고 하루 한도에도 들지
않는다.** 아침 메일이 공짜인 이유가 이것이다.

### 3. 비밀 둘을 넣는다

Workers → 해당 워커 → **설정 → 변수 및 암호**. 종류를 **암호(Secret)** 로 고른다.

| 이름 | 값 |
| --- | --- |
| `DIGEST_KEY` | 드롭박스 `board_keys.txt` 의 `DIGEST_KEY` |
| `PREVIEW_TOKEN` | 아침 메일을 손으로 한 통 부칠 때만 쓴다 |
| `LEDGER_TOKEN` | 해치운 할 일 기록을 여닫는 키 |

한 번 넣으면 다시 배포해도 지워지지 않는다.

### 3-1. 기록을 놓는다

이름공간 `loggia-ledger` 를 만들어 `wrangler.jsonc` 에 이어 두었다.
2026년 8월 1일에 붙였다. 칸은 `board` 하나뿐이다.

이것이 없어도 판은 온전하다. 네모를 눌러도 그 표시가 이 기기에만 남을 뿐이다.

### 4. 주소를 붙인다

Workers → 해당 워커 → **설정 → 도메인 및 경로 → 사용자 지정 도메인** 에
`loggia.moonilsun.com`. DNS 는 클라우드플레어가 스스로 적는다. 증명서도
알아서 나온다. 깃허브 페이지에 붙일 때 필요하던 회색 구름이니 Enforce HTTPS 니
하는 할 일이 여기서는 없다.

## 부쳐 보기

크론을 기다리지 않고 한 통 보내려면

```
https://loggia.moonilsun.com/send?k=<PREVIEW_TOKEN>
```

이 주소는 판의 내용을 어떤 경우에도 돌려주지 않는다.
「부쳤습니다」 한 줄만 돌아온다. 결과는 편지함에서 본다.

자리를 찾은 요청은 파일이 먼저 나가고 못 찾은 요청만 워커가 받는다.
그래서 `/` 는 `index.html` 이 나가고 `/send` 는 워커에게 닿는다.

## 시간

크론은 UTC 로만 돈다. 서울은 서머타임이 없으므로 늘 아홉 시간 앞선다.

| 서울 | `crons` |
| --- | --- |
| 아침 07시 | `0 22 * * *` |
| 아침 08시 | `0 23 * * *` |
| 평일 아침 07시 | `0 22 * * 0-4` |

평일만 받고 싶으면 요일 칸을 `0-4` 로 둔다. UTC 로 하루 앞당겨졌으므로
일요일부터 목요일이 서울의 월요일부터 금요일이다.

## 편지에 무엇이 실리나

| 자리 | 무엇 | 언제 나오나 |
| --- | --- | --- |
| 오늘 하나 | 진행 중인 것의 첫 할 일 | 마감이 가장 가까운 것. 지난 마감이 있으면 그것이 먼저 |
| 지난 마감 | 넘긴 마감 | 다섯까지. 더 있으면 몇 개 더 있다고 적는다 |
| 이레 안 | 다가오는 마감 | 이레 안 |
| 답이 늦다 | 낸 것 | 그 지면의 보통보다 오래 기다린 것. 보통을 모르면 마흔닷새 |
| 멎어 있다 | 손이 가지 않은 것 | 스무 날 넘게. 넷까지 |
| 돌아온다 | 되풀이 마감 | 열흘 안. 셋까지 |

되풀이만은 `D-` 를 쓰지 않고 `4일 뒤` 라고 적는다. 참된 마감이 아닌데 같은
글자를 쓰면 눈이 헷갈리기 때문이다.

편지의 옷은 판의 옷과 같다. 왼쪽 막대의 색이 결을 말한다. 붉음은 급하다,
주황은 다가온다, 파랑은 남을 기다린다, 회색은 멎었다. 어두운 낯빛에서는
초점 상자가 통째로 뒤집힌다. 판이 그러하므로 편지도 그렇게 둔다.

날수는 전부 부치는 그 순간에 센다. 판이 두 주 동안 올라가지 않아도
편지의 숫자는 낡지 않는다.

## 기록

네모를 누르면 그 자리에서 줄이 그어지고, 아래 막대에 「끝낸 일 N」이 뜬다.
**저장**을 누를 때 한 번에 보낸다. 누를 때마다 보내면 부질없는 왕복이 는다.
저장하지 않고 창을 덮으면 그때 흘려보낸다.

기록은 워커의 KV 에 있으므로 **휴대전화에서 그은 줄이 노트북에서도 보인다.**
판을 열 때마다 기록을 읽어 표시를 맞춘다.

```
GET  /done?k=<LEDGER_TOKEN>   끝냈다고 표시한 것을 읽는다
POST /done?k=<LEDGER_TOKEN>   {set:{...}, del:[...]} 를 겹쳐 적는다
GET  /add?k=<LEDGER_TOKEN>    새로 적어 넣은 할 일
POST /add?k=<LEDGER_TOKEN>    같은 형식
GET  /edit?k=<LEDGER_TOKEN>   고치거나 지운 할 일
POST /edit?k=<LEDGER_TOKEN>   같은 형식
```

## 데이터에 반영하기

2026년 8월 2일부터 워커가 **10분마다** 이 기록을 `public/data.enc` 에 직접
반영한다. 예전에는 사람이 다음 갱신 때 옮겼다.

```
*/10 * * * *  →  flush()
   KV 를 읽는다. 비었으면 아무것도 하지 않는다
   깃허브에서 public/data.enc 를 받아 푼다
   끝낸 할 일을 빼고, 고친 것을 고치고, 새로 적은 것을 넣는다
   다시 암호화하고 digest.enc 도 새로 만든다
   둘을 한 커밋으로 올린다
   그 다음에 KV 를 비운다
```

KV 를 마지막에 비우는 게 중요하다. 먼저 비우면 올리다 실패했을 때 사용자가
체크한 게 사라진다. 나중에 비우면 최악의 경우 한 번 더 반영할 뿐이고,
같은 걸 두 번 반영해도 결과는 같다.

10분을 기다리지 않고 지금 해 보려면 `GET /flush?k=<PREVIEW_TOKEN>`.

**이 기능은 시크릿 두 개가 있어야 돈다.** 없으면 조용히 건너뛴다.

| 시크릿 | 무엇 |
| --- | --- |
| `PAGE_KEY` | 암호에서 뽑은 32바이트 키를 base64 로. `tools/pagekey.js` 가 뽑는다 |
| `GITHUB_TOKEN` | 저장소에 쓴다. `eeruwang/loggia` 의 contents 쓰기만 있으면 된다 |

**암호 자체는 넣지 않는다.** 클라우드플레어 Workers 는 PBKDF2 반복을 10만 번까지만
허용하는데 이 보드는 60만 번을 쓴다. 그래서 워커가 암호에서 키를 뽑을 수 없다.
미리 뽑아 넣는다. 덕분에 사람이 기억하는 암호는 클라우드플레어에 남지 않는다.

```bash
node tools/pagekey.js public/data.enc "<암호>"
```

그 대신 **솔트를 고정한다.** 키가 솔트에 매여 있기 때문이다. `publish.sh` 도
다시 암호화할 때 저장소에 있던 솔트를 그대로 쓴다. 솔트는 비밀이 아니고 암호가
길므로 같은 값을 계속 써도 안전하다. 덤으로 브라우저가 세션에 넣어 둔 키가
갱신 뒤에도 살아 있어 다시 열 때 기다림이 없다.

솔트가 어쩌다 바뀌면 워커가 「PAGE_KEY 로 열리지 않습니다」라고 말한다.
그때 `pagekey.js` 로 다시 뽑아 넣으면 된다. 데이터가 상하지는 않는다.

`PAGE_KEY` 를 워커에 두면 클라우드플레어가 보드 내용을 읽을 수 있게 된다.
그 값을 치르고 사람 손을 없앤 것이다. 2026년 8월 2일에 그렇게 정했다.

### 손으로 시험하려면

`wrangler.jsonc` 를 본떠 시험용 설정을 하나 만들고, `GITHUB_API` 에 흉내 낸
서버 주소를 넣으면 진짜 저장소를 건드리지 않고 돌려 볼 수 있다.
그 설정 파일에는 암호가 들어가므로 저장소에 올리지 않는다
(`.gitignore` 의 `wrangler.*-test.jsonc`).

## 할 일을 손으로 추가하기

화면 오른쪽 아래에 단추 하나가 있다. 누르면 작은 상자가 열리고
어느 항목에 넣을지, 무엇을, 언제까지를 고른다. 단추를 카드마다 두지 않는 것은
카드가 열이면 단추도 열이 되어 눈이 어지럽기 때문이다.

**저장은 곧바로 간다.** 체크와 달리 모으지 않는다. 적어 둔 글자를 잃으면
안 되기 때문이다. 다만 가는 곳은 워커의 기록일 뿐, 깃허브의 데이터가 아니다.

날짜를 함께 적으면 그 할 일이 제 D-day 를 갖는다.
셈은 판을 열 때마다 다시 하므로 낡지 않는다.

이 할 일은 **이튿날 아침 메일에도 함께 실린다.** 밤에 적은 것이 아침에 없으면
적은 보람이 없다. 데이터에 들어가는 것은 다음 갱신 때이고, 그때까지
「새로 적음」이라고 붙여 두는 것은 아직 참이 아닌 것을 참인 척 그리지
않기 위해서다.

## 석 달에 한 번, 돌아보는 편지

1월 · 4월 · 7월 · 10월의 첫날 아침에는 다른 편지가 온다.
지난 석 달에 낸 것과 끝난 것, 두 달 넘게 멈춘 것, 아직 답이 없는 것,
그리고 나침반의 줄들이 실린다.

이 편지는 답하지 않는다. 숫자를 늘어놓고 나침반을 옆에 세운 뒤 그 둘이
맞는지를 묻고 만다. 「지난 30일」은 셈이지 성찰이 아니고, 셈은 무엇이
있었는지를 말할 뿐 그것이 어디로 가고 있었는지는 말하지 못한다.

## 키가 둘인 까닭

보드 암호는 사람이 손으로 치는 것이라 엔트로피가 낮아 PBKDF2 를 육십만 번
돌려야 한다. 그 셈은 무료 판의 십 밀리초를 훌쩍 넘긴다. 그래서 워커에게는
처음부터 무작위 256비트를 따로 주었다. 반복 계산이 없으니 푸는 데 1밀리초도
들지 않는다.

`DIGEST_KEY` 로는 `digest.enc` 만 열린다. `data.enc` 는 열리지 않는다.
워커는 아침 메일에 필요한 만큼만 볼 수 있다.
